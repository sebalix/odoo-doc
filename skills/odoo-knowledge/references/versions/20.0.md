# Odoo 19.0 → 20.0

## Python Code

| Old | New |
|-----|-----|
| `ir.config_parameter.get_param(key)` | `get_str(key)` / `get_bool(key)` / `get_int(key)` / `get_float(key)` |
| `set_param(key, value)` | `set_str` / `set_bool` / `set_int` / `set_float` |
| `registry.clear_cache()` | `transaction.invalidate_ormcache()` |
| `_rec_names_search = ['name']` (list) | `('name',)` (tuple) |
| `read_group(domain, fields, groupby, ...)` (dict output, overridable) | `read_group(domain, groupby, aggregates, having, ...)` returns `list[tuple]` and is `@typing.final` (cannot be overridden); override `_read_group` instead |
| `odoo.osv.expression` | removed — use `odoo.fields.Domain` (the module was still importable in 19.0) |

**Notes:**
- The new `read_group()` is the tuple-based API introduced in 17.0 as
  `_read_group()`; results are tuples of groupby values (ids for relational
  fields) + aggregate values — no more dicts with `__domain`/`__count` keys

**Raw SQL:**

| Old | New |
|-----|-----|
| interpolated identifiers in `cr.execute` | `odoo.tools.SQL` wrapper / `SQL.identifier(name)` |

## Security data files

`ir.model.access` and `ir.rule` are merged into a single `ir.access` model
(`ir.rule` and `ir.model.access` no longer exist in 20.0).

| Old | New |
|-----|-----|
| `security/ir.model.access.csv` columns `perm_read,perm_write,perm_create,perm_unlink` (0/1) | `security/ir.access.csv` columns `operation` (subset of `crud`: `c`, `r`, `u`, `d`, `cr`, `ru`, `crud`, ...) and `domain` |
| record rules in XML (`<record model="ir.rule">`) | restriction rows in `ir.access.csv`: group-less row + `domain` column |
| separate group rows and rule files | one CSV: a group row grants, a group-less row restricts |

An official conversion script ships in the Odoo source tree:
`odoo/upgrade_code/19.4-00-ir-access.py` (see odoo/odoo#166359 for
conversion examples).

## XML Views

| Old | New |
|-----|-----|
| `t-raw` | removed — `t-out` only |
| `t-esc` | removed from the server QWeb engine — `t-out` |
| `widget="selection_badge"` | `badges_selection` (selection fields) / `badges_many2one` (many2one fields) |

**Data files:**

| Old | New |
|-----|-----|
| `<field name="..." type="base64" file="..."/>` | `type="bytes"` |

**QWeb templates:**

| Old | New |
|-----|-----|
| `t-set` before `t-call` to pass variables | variables as attributes on the `t-call` tag: `<t t-call="tpl" var="value"/>` (`var.f` for format strings, `.translate` for translatable text) |

**Tests:**

| Old | New |
|-----|-----|
| `BaseCommon` test classes run as superuser | tests run as a plain internal user (`base.group_user`); set `_test_user_groups = None` on the class to keep the superuser behavior |

## JavaScript

Odoo 20 ships OWL 3. Hooks (`useState`, `useRef`, `useEffect`, `useEnv`,
`reactive`, ...) and template directives (`t-esc` → `t-out`, `t-ref`,
`t-slot`, parametric `t-call`) changed. Automated conversion:
`odoo/upgrade_code/owl3-migration.py` via the `odoo-bin upgrade-code` CLI.

The `odoo/upgrade_code/` directory in the Odoo source tree ships
conversion scripts for machine-convertible changes (for 20.0: the
`19.x-*` and `owl3-migration.py` scripts). Run `odoo-bin upgrade-code`
on the module before manual migration work.
